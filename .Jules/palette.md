## 2024-03-20 - Adding Keyboard Accessibility to Non-Semantic Components
**Learning:** Custom UI components in this application (such as `MCButton`, `MCSlot`, and `MCItem`) frequently use non-semantic HTML tags like `div` or `img` despite being interactive (having `onClick` handlers). This pattern completely breaks keyboard accessibility, as these elements are not natively focusable or interactable via the keyboard. When implementing custom `onKeyDown` handlers for these components to support the Space key, it is crucial to call `e.preventDefault()` to stop the browser's default behavior of scrolling the page down.
**Action:** When creating or updating non-semantic interactive components in this design system, always explicitly add `role="button"`, `tabIndex={0}`, an `onKeyDown` handler for 'Enter' and 'Space' (with `e.preventDefault()` for Space), and existing Tailwind focus utility classes (e.g., `focus-visible:ring-2 focus-visible:ring-white focus-visible:outline-none`) to ensure full keyboard accessibility.
